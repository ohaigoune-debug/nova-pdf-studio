## 4) أداء واستقرار (Node 22 على Linux — **ليس** iPhone)
| العملية | الزمن |
|---|---|
| إنشاء PDF من 300 صفحة (283 KB) | 358 ms |
| دمج 300 + 300 ← 600 صفحة | 173 ms |
| تقسيم كل 50 صفحة ← 6 ملفات، لا صفحة مفقودة | 69 ms |
| تدوير 300 / علامة مائية 300 / ترقيم 300 / ضغط | 69 / 144 / 147 / 59 ms |
| فتح 300 صفحة بـ pdf.js + نص الصفحة 300 | 200 + 49 ms |
| 20 دورة «تعديل ثم حفظ» متتالية | 161 ms — الملف صالح، الحجم ×1.4 فقط |
| 1000 فاتورة × 3 أسطر + دفعات (معاملة واحدة) | 856 ms |
| عرض أول 100 / الصفحة العاشرة | 6 / 7 ms |
| حجم القاعدة بـ 1000 فاتورة | 1.7 MB، إعادة فتحها سليمة والمبالغ مطابقة |

مرشحات المسح على صورة 2400×1800 (Node): محسّن 568 ms · رمادي 368 ms · أبيض وأسود 93 ms (على iPhone أبطأ؛ يُطبَّق مرة لكل صفحة ومرشح).

ذروة الذاكرة في العملية كلها ≈ 373 MB (Node نفسه + pdf.js). **على iPhone لم يُقَس الأداء ولا الذاكرة** (WKWebView أبطأ من Node، والأجهزة القديمة أكثر).

اكتُشف بهذه الاختبارات: قائمة الفواتير كانت تقف عند 300 — أصبحت تعرض 200 ثم «عرض المزيد».
