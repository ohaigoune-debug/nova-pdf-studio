# مدرسة — منصة اللغة والأدب العربي (SaaS متعدد الأساتذة)

منصة تعليمية عربية (RTL أولاً) لطلبة الثانوي والبكالوريا تجمع: محتوى عام، إدارة أفواج وطلاب لكل أستاذ في مساحة معزولة، تسجيل بأكواد، حضور ذكي ببطاقة QR ديناميكية وقارئ USB/Bluetooth، قاعدة الغيابات والتعليق، ملف شامل لكل طالب، ولاحقاً الواجبات والتصحيح بمساعدة الذكاء الاصطناعي وخريطة المهارات.

الوثائق: [الهندسة](docs/ARCHITECTURE.md) · [قاعدة البيانات](docs/DATABASE_SCHEMA.md) · [الصلاحيات](docs/PERMISSIONS.md) · [خطة التنفيذ](docs/IMPLEMENTATION_PLAN.md) · [الأمان](docs/SECURITY.md) · [النشر](docs/DEPLOYMENT.md)

## التشغيل محلياً (بلا خادم قاعدة بيانات)

```bash
cd platform
cp .env.example .env.local        # ثم غيّر SESSION_SECRET و QR_TOKEN_SECRET
npm install
npm run db:seed                   # يطبّق الـMigrations ويزرع بيانات تجريبية عربية على PGlite (./data)
npm run dev                       # http://localhost:3000
```

## المسار الكامل (Vertical Slice) — يعمل ومختبَر

المشرف ينشئ أستاذاً → الأستاذ ينشئ فوجاً → يولّد أكواداً (طباعة/CSV) → الطالب ينشئ حساباً ويدخل الكود → ينضم تلقائياً → الأستاذ يبدأ حصة → الطالب يفتح بطاقة الحضور (QR موقّع يتجدد كل 60 ث) → الأستاذ يمسح في وضع السكانر → يُسجَّل حاضراً/متأخراً فوراً مع صوت → إنهاء الحصة يحوّل الغائبين إلى "غياب غير مبرر" → 4 غيابات تعلّق التسجيل (بلا حذف) → تبرير الغياب وإعادة التفعيل يدوياً → كل شيء يظهر في ملف الطالب وخطه الزمني وسجل التدقيق.

## واجهة API (للجوال)

كل الخدمات مكشوفة تحت `/api/v1` بنفس الجلسة (كوكي أو `Authorization: Bearer <token>`):

- `POST /api/v1/auth/login` → token · `GET /api/v1/auth/me`
- `GET /api/v1/student/attendance-token?groupId=` → رمز QR موقّع
- `GET|POST /api/v1/teacher/sessions` · `POST /api/v1/teacher/sessions/:id/close` · `GET /api/v1/teacher/sessions/:id/attendance`
- `POST /api/v1/attendance/scan` `{ classSessionId, token }`
- `GET /api/v1/files/:id?exp=&sig=` → تنزيل ملف عبر رابط موقّع فقط
- `POST /api/v1/jobs/run` (ترويسة `x-cron-secret`) → تشغيل دفعة من المهام الخلفية

## الواجبات (المرحلة 4)

الأستاذ ينشئ واجباً ويسنده لأفواج أو طلاب محددين → الطالب **يكتب إجابته نصاً كرسالة** (مسودة تُحفظ تلقائياً، ثم إرسال نهائي) → الأستاذ يقرأ ويعلّق في سلسلة الرسائل ويعتمد التصحيح (نقطة، ما أحسن فيه، ما يحتاج تحسينه) → تصل الطالب علامة معتمدة ورسالة تصحيح، ويستطيع الردّ. لا تصوير ولا OCR؛ المرفقات مواد داعمة فقط.

## الاختبارات والشبكات والمهارات (المرحلة 5)

- **محرك اختبارات** بسبعة أنواع أسئلة (اختيار من متعدد، صح/خطأ، إجابة قصيرة، ملء فراغ، مطابقة، ترتيب، مقال) مع تصحيح آلي فوري (تطبيع عربي للهمزات والتاء المربوطة والتشكيل، درجة جزئية للفراغات والمطابقة)، مؤقّت، حدّ محاولات، ومقال يحتاج مراجعة الأستاذ قبل ظهور النتيجة. الأسئلة تُقفل بعد أول محاولة، ومفاتيح الإجابة لا تُرسل للطالب قبل اعتماد النتيجة.
- **شبكات تصحيح (Rubrics)** ببنود ونقاط ومهارة لكل بند؛ قوالب عامة يوفّرها المشرف وشبكات خاصة بكل أستاذ. التصحيح بند‑بند يحسب النقطة ويغذّي خريطة المهارات.
- **محرك مهارات**: كل اختبار أو تصحيح يحدّث درجة المهارة (متوسط متحرك) وثقتها وتاريخها؛ خريطة مهارات للطالب مع اقتراح دروس علاجية، ونقاط ضعف الفوج للأستاذ.
- **رؤى مبنية على البيانات**: خريطة حرارية للحضور، مهارات الفوج الأضعف، الطلاب المتخلّفون عن آخر واجبين.
- اختبار ذاتي عام على الصفحة العمومية بلا حساب.

## التصحيح بمساعدة الذكاء الاصطناعي (المرحلة 6)

الأستاذ يضغط «اطلب اقتراح تصحيح» على إجابة نصية (أو يفعّل المشرف التقييم التلقائي عند كل إرسال) → مهمة خلفية تستدعي `AIProvider` → اقتراح: نقطة وتوزيع على بنود الشبكة، نقاط قوة/ضعف، أخطاء، مهارات ظاهرة وتحتاج تقوية، ملاحظة مقترحة → الأستاذ يعبّئ النموذج بالاقتراح ويعدّله ثم يعتمد (APPROVED/EDITED) أو يرفضه (REJECTED) → عندها فقط تصل الطالب علامة ورسالة تصحيح.

**قواعد ثابتة:** الذكاء الاصطناعي لا يكتب علامة أبداً (مختبَر)، الطالب لا يرى وجود الاقتراح، المفاتيح في الخادم فقط، وكل فشل يُعرض للأستاذ كرسالة عربية عامة.

- بلا إعداد: مزوّد تجريبي حتمي (يقيس ملامح شكلية للنص العربي) لتشغيل المسار كاملاً محلياً.
- مزوّد حقيقي: `AI_PROVIDER=anthropic` + `AI_API_KEY=…` (+ `AI_MODEL` اختياري).
- المهام: تُنفَّذ داخل الخادم تلقائياً، أو عبر Cron خارجي `POST /api/v1/jobs/run` بترويسة `x-cron-secret: $CRON_SECRET`، أو `npm run jobs:worker`.
- صفحة «تحليلات الذكاء الاصطناعي» للأستاذ: حقائق من البيانات + ملخص وتوصيات الحصة القادمة يولّدها المزوّد كمهمة.
- **تمارين علاجية بضغطة زر**: لكل مهارة ضعيفة في الفوج يولّد المزوّد مسودة اختبار (غير منشورة) يراجعها الأستاذ وينشرها.
- **تحليل ملف الطالب**: ملخص ونقاط قوة/ضعف وتوصيات من حقائق الحضور والمهارات والعلامات، للأستاذ وحده.

## التحليلات والتقارير والتعلّم التكيفي (المرحلة 7)

- **ربط الغياب بالمستوى** كتوصية: يقارن النظام متوسط مهارات الأكثر غياباً بالمنتظمين داخل الفوج ويقترح التواصل وملخصات الحصص الفائتة.
- **خطة التقوية للطالب**: للمهارات الأضعف ⇒ درس، تمارين، اختبار قصير من المحتوى المتاح له، تتحدّث بعد كل تقييم.
- **بطاقات قابلة للطباعة (PDF)**: بطاقة متابعة الطالب بتوقيع الولي وتقرير الفوج، من المتصفح مباشرة.
- **تقارير CSV كمهام خلفية**: حضور الفوج (حصة × طالب)، علامات الفوج، خريطة مهارات الفوج، قائمة الطلاب — تُحفظ كملفات خاصة وتُنزَّل برابط موقّع، مع إشعار عند الجاهزية.

## التحصين والإنتاج (المرحلة 8)

- **الحدّ من المحاولات** في قاعدة البيانات (دخول، تسجيل، أكواد، مسح، إعادة تعيين، AI) برسائل عربية.
- **CSP بـ nonce** لكل طلب + HSTS وبقية الترويسات، مُتحقَّق منها بمتصفح حقيقي بلا انتهاكات.
- **نسيت كلمة السر**: رابط بريد مجزّأ صالح 30 دقيقة لمرة واحدة، يُنهي الجلسات القديمة؛ مزوّد بريد قابل للتبديل (console/Resend/Webhook).
- **PWA + إشعارات الدفع**: تثبيت على الهاتف، صفحة بلا اتصال، وإشعارات تصل الجهاز حتى والتطبيق مغلق (`npm run push:keys` ثم ضبط `VAPID_*`).
- **تخزين S3** متوافق (R2/MinIO/Supabase) عبر `STORAGE_DRIVER=s3`، وصيانة دورية تلقائية.
- **النشر**: `Dockerfile` + `docker-compose.yml` (Postgres + app + cron) — التفاصيل في [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).
- **ثلاث لغات للموقع العام** (عربي/فرنسي/إنجليزي) بمبدّل في الرأس؛ الاتجاه والرسائل تتبع اللغة، واللوحات الداخلية عربية أولاً.
