# خطة التنفيذ — IMPLEMENTATION_PLAN

المبدأ: **Vertical Slice** حقيقي يعمل من طرف إلى طرف قبل التوسّع. بعد كل مرحلة: `npm run typecheck && npm run lint && npm test` ثم تشغيل التطبيق.

## المرحلة 1 — الأساس ✅

- [x] Next.js 15 + TS strict + Tailwind + مكوّنات UI بأسلوب shadcn + RTL + Dark Mode
- [x] Drizzle schema كامل للجداول الأساسية + Migrations + PGlite/Postgres client
- [x] مصادقة: تسجيل، دخول، خروج، جلسات في DB، كوكي httpOnly، إدارة الأجهزة
- [x] الأدوار + حرّاس الخادم (`requireActor`, `requireRole`)
- [x] i18n (ar أساسي، بنية لإضافة fr/en)
- [x] الأصداف: Public / Student / Teacher / Admin (Sidebar + TopBar + Navigation)
- [x] `AppError` + رسائل عربية، سجل تدقيق، إشعارات داخل التطبيق

## المرحلة 2 — الأفواج والتسجيل ✅

- [x] Storage: رفع ملفات (Local adapter، S3/Supabase Storage لاحقاً بنفس الواجهة) + روابط موقّعة تنتهي بعد 10 دقائق + تحقق MIME/الحجم
- [x] الواجبات + الإسناد (فوج/أفواج/طلاب محددون) + إشعار الطلاب + لوحة الإجابات ونسبة الإنجاز

## المرحلة 6 — التصحيح بالذكاء الاصطناعي

- [x] **Skills Engine** (نُفِّذ مبكراً): `student_skills` بمتوسط متحرك وثقة تتراكم + `student_skill_history`؛ يُغذَّى من الاختبارات (لكل مهارة سؤال) ومن تصحيح الأستاذ (مهارة الواجب وبنود الشبكة)؛ خريطة مهارات للطالب وللأستاذ، والمهارات الضعيفة المشتركة في الفوج، ومحتوى مقترح لتقوية المهارات الضعيفة (تعلّم تكيفي مبسّط)
- [x] `AIProvider` (`evaluateEssay`, `generateTeacherInsights`) + مزوّد تجريبي حتمي + مزوّد Anthropic حقيقي يُفعَّل من البيئة (`AI_PROVIDER`, `AI_API_KEY`, `AI_MODEL`)؛ لا مفتاح في المتصفح
- [x] طابور `jobs` حقيقي (التقاط بقفل، إعادة محاولة بتراجع أسّي، عامل داخلي + Cron `POST /api/v1/jobs/run` + `npm run jobs:worker`)
- [x] التصحيح على النص المكتوب: إجابة نصية → Job → اقتراح (نقطة، توزيع على بنود الشبكة، قوة/ضعف/أخطاء/مهارات، ملاحظة) → لوحة الأستاذ (تعبئة النموذج/تعديل/رفض) → تظهر للطالب كرسالة تصحيح بعد الاعتماد فقط. لا OCR (قرار مالك المنصة)
- [x] Teacher Review في `teacher_reviews` (APPROVED/EDITED/REJECTED) + قاعدة "AI لا يكتب فوق علامة الأستاذ" مختبَرة + إخفاء كامل عن الطالب (الحالة والنصوص) + تقييم تلقائي اختياري عند الإرسال يفعّله المشرف
- [ ] `analyzeStudent` و`generateExercises` (توليد تمارين علاجية) — لاحقاً فوق نفس الواجهة

## المرحلة 8 — التحصين والإنتاج

- [x] Rate limiting مخزَّن في قاعدة البيانات (`rate_limits`، نافذة ثابتة، يعمل مع عدة نسخ): الدخول (IP + بريد مجزّأ)، التسجيل، تفعيل الأكواد، المسح، إعادة التعيين، طلبات AI
- [x] CSRF: Server Actions تتحقق من Origin (Next) + `assertSameOrigin` على Route Handlers؛ CSP بـ nonce لكل طلب (`strict-dynamic`، لا سكربت مضمّن) + HSTS + COOP، مُتحقَّق منها بمتصفح حقيقي (Playwright) بلا أي انتهاك
- [x] إعادة تعيين كلمة السر بالبريد: رمز مجزّأ صالح 30 دقيقة لمرة واحدة، لا يكشف وجود الحساب، يُنهي كل الجلسات؛ `Mailer` مجرّد (console / Resend / Webhook)
- [x] مهمة صيانة `CLEANUP` كل 24 ساعة (جلسات، nonces، رموز إعادة تعيين، حدود المحاولات، مهام قديمة)
- [x] RLS: `npm run db:rls` يطبّق `rls.sql` على Postgres/Supabase؛ Signed URLs للملفات (منذ المرحلة 4)
- [x] تخزين سحابي: محوّل S3 متوافق (AWS/R2/MinIO/Supabase) بتوقيع SigV4 مُختبَر بمتجهات AWS الرسمية، يُفعَّل بـ `STORAGE_DRIVER=s3`
- [x] PWA: manifest + service worker (غلاف بلا اتصال، تخزين الأصول، معالج push جاهز) + صفحة `/offline`
- [x] Docker (متعدد المراحل، standalone) + docker-compose (Postgres + app + cron) + `docs/DEPLOYMENT.md`
- [x] Push Notifications: اشتراكات لكل جهاز (`push_subscriptions`) + إرسال Web Push بلا مكتبات (RFC 8291 aes128gcm مُختبَر بمتجه RFC الرسمي، VAPID ES256) كمهمة `PUSH_DISPATCH` تُنشأ تلقائياً مع كل إشعار داخل التطبيق؛ حذف الاشتراكات الملغاة (410) والفاشلة المتكررة؛ زر تفعيل في صفحة الإشعارات
- [ ] تقارير PDF، `analyzeStudent`/`generateExercises`، لغات fr/en
